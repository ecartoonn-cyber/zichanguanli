## 4. 持仓结构、存储和计算逻辑

### 4.1 当前 state 形状

代码中的初始 state 为 `{ holdings: [], profile: {}, profileSavedAt: null }`。持仓对象从表单保存时至少包含：

`id, platform, assetType, market, name, code, value, currency, pnlValue, pnlBasis, updatedAt, verifiedType, nameVerified, lookupSource, manualName`

这只是前端对象形状，不是版本化的数据契约。没有 `schemaVersion`、数据库约束、迁移函数或服务端验证。用户现有浏览器数据不能从当前目录读取，也不能据此确认记录数量或旧记录具体字段。

### 4.2 存储与恢复

- 所有问卷与持仓 state 写入浏览器 `localStorage`；更换浏览器/设备或清理站点数据会导致记录不可见或丢失。
- 导出可以保存 JSON；导入会在确认后以文件内容替换现有 state。未见 schema 校验、导入差异预览、字段级迁移或撤销。
- 清除数据有确认框；单条持仓删除有确认框，但没有撤销。
- 没有云端备份、访问控制、加密/密钥方案或审计日志。浏览器本地数据的安全依赖设备与浏览器配置。
- 存储失败/配额不足的错误处理未见。

### 4.3 盈亏及图表

- 金额口径的累计盈亏：`cost = current amount - pnl`，`return = pnl / cost`；累计比例则按输入比例展示/反推隐含成本。非累计口径不纳入收益率。
- 产品收益率卡片和分组图表属于估算值，不等同平台真实收益率；未记录成本流水、分红、手续费或赎回对成本基数的影响。
- 分组按“产品类型/市场范围 + 币种”计算 `sum(P&L) / sum(implied cost)`，不是算术平均；无可计算数据时显示无数据覆盖。两种视图分别是产品类型与市场，不提供国家/地区、资产类别、平台、行业或持仓钻取。
- 目前图表只是 CSS 条形显示，没有坐标刻度、交互筛选、点击钻取、图表导出或可复用图表数据契约。
- 当前市场字段仅有“国内/海外/全球混合/待分类”，无地域来源、分类时间、置信度或产品底层披露数据。

## 7. 最小改造方案

1. **冻结当前文件为原型基线。** 在 Git 初始提交前，单独备份当前 HTML 和 JSON 导出；不要改写原文件作为第一步。
2. **创建可审阅的项目骨架。** 推荐 Vite + React + TypeScript；旧页面按页面功能逐步迁移，短期保留本地工作能力。
3. **先定义并校验持仓契约。** 由现有对象映射到版本化 `Holding`；保留原始字段和值，新增 `schemaVersion` 和迁移记录；不新增成本/交易流水要求。
4. **拆分纯计算包。** 计算输入为原始录入值和时间戳；输出为 estimates、资格状态和计算说明；测试通过后再替换页面里当前计算函数。
5. **建立单条产品资料 Adapter。** 保持查名为辅助，明确代码一致、来源、抓取时间、是否用户确认；失败不清空名称、不将候选当事实。
6. **备份后实现本地导入导出升级。** 批量导入预览、重复检查、差异摘要、提交确认和恢复点先于任何云迁移。
7. **在确认云端目标后做最小后端。** 第一阶段只做 auth、持仓 CRUD、任务记录与一个真实公开行情数据源；不要同时加入全部宏观指标与 AI。
8. **先跑通一个端到端任务。** 数据拉取 → 保存 source/fetched/data_as_of → 计算 → 记录 run status → 页面显示新鲜度；失败时只展示失败和已有数据时间。

### 可保留

- 现有页面产品语言、问卷问题、当前表单流程及无交易权限原则。
- 当前 JSON 导出格式作为旧数据迁移输入。
- 现有名称核对 UX 和可手工补录路径，但查询实现应替换为可诊断 provider。
- 当前收益率思路仅作为一种 estimate，必须用独立测试证明口径并明确数据限制。

### 必须重做/补齐

- 单文件结构的模块边界（渐进抽取，不要求一次重写）。
- 未版本化的持仓契约、分类维度、时间戳与来源字段。
- 本地-only 持久化无法支撑的远程 API、权限、云数据库、定时作业。
- 计算测试、迁移测试、错误/任务日志、导入保护与备份恢复演练。
- 市场数据源条款/频率/时效评估、定时更新、过期状态与来源展示。
- 安全的服务端 AI 调用（只在用户明确选择模型和数据发送范围后实施）。

## 8. 建议架构（待确认，不是现状声明）

```text
React + TypeScript 前端
  ├─ 持仓、画像、总览、风险、市场监控、AI 研究、数据状态
  ├─ 表单校验与交互；不放供应商密钥
  └─ 使用版本化 API 契约
          │ HTTPS + 用户会话/鉴权
          ▼
应用 API / 领域服务（TypeScript）
  ├─ 持仓校验与迁移
  ├─ 产品资料 Provider Adapter
  ├─ 纯计算包（收益、敞口、覆盖率、过期判断）
  ├─ 市场数据 Adapter
  ├─ AI 请求代理与输出校验（后续阶段）
  └─ 数据最少化、鉴权、日志脱敏
          │
          ├──────── PostgreSQL：持仓、产品资料、来源快照、任务与报告
          └──────── 定时任务：取数 → 校验 → upsert → 重算 → 健康记录
```

架构约束：

- `Holding` 原始录入、来源数据、计算结果、AI 推断分层保存，不互相覆盖。
- 计算逻辑由普通代码执行；AI 只能获得经筛选的上下文并产出经 schema 校验的研究结果。
- 市场任务与 AI 报告分开；市场关键数据拉取失败或过期时，不将旧数据标成当天报告事实。
- 定时任务以 `run_id`、唯一键/幂等 upsert、防重锁和明确的失败状态实现可重跑。
- 用户可导出、恢复、删除数据；云迁移前必须显示迁移数量、字段映射和差异并保留旧备份。

## 9. 技术选型比较与暂定建议

### 9.1 前端与图表

| 选择 | 适配情况 | 优点 | 代价/风险 | 暂定判断 |
|---|---|---|---|---|
| 保留原生单文件 HTML | 保持现有原型 | 零构建、可直接打开、易备份 | 多页面/表单/图表/服务状态继续加剧耦合；测试与类型契约弱 | 保留为迁移基线，不作为完整升级目标 |
| React + TypeScript + Vite | 当前没有框架约束；适合交互较多的 SPA | 组件边界、类型契约、成熟生态；可逐步移植 | 引入构建、依赖与维护；必须先有 Git 和测试底座 | **暂定推荐**，但开始 Gate 1 前核对用户偏好及设备/托管要求 |
| Vue + TypeScript + Vite | 同样可做 SPA | 易拆组件、表单开发直接 | 当前无 Vue 代码可复用；再加一个选型分支无收益 | 可行备选；除非用户偏好 Vue，不同时混用 |
| 无框架 TypeScript 模块化 | 原型可轻量渐进升级 | 依赖更少；保留 Vanilla UI | 复杂多页/表格交互仍需自行搭架子 | 若用户要继续保持单文件简单，可作为过渡 |

图表候选为 Apache ECharts（互动、缩放、数据维度丰富）或保留自绘（初始功能少、依赖最小）。若目标确实包含地区钻取、筛选、多个指标，建议只采用 ECharts；先通过首个原型确认移动端与可访问性，再添加依赖。当前项目没有任何图表库。

### 9.2 后端与定时任务托管

| 方案 | 本项目匹配点 | 主要限制/需要核实 | 建议角色 |
|---|---|---|---|
| **CloudBase 云函数 + 数据库** | 中文资料、Node/Python 函数、定时触发、数据库/身份/云存储服务同一套；若用户已有腾讯云资源，可能减少账户迁移 | 本地没有 CloudBase 资源证据；区域、海外数据源可达性、使用计费、数据库规则/认证与导出需实际核验 | 若确认已有腾讯云账号/资源或境内网络优先，作为首选候选。官方文档说明云函数可由 Cron 定时触发并与数据库/存储/认证集成：[云函数](https://cloud.tencent.com/document/product/876/46899)、[定时触发器](https://cloud.tencent.com/document/product/583/9708) |
| **Supabase（Postgres + Edge Functions + Cron）** | 一体化 Postgres、服务端函数、数据库任务运行历史；适合结构化持仓和报告 | 本地无项目可复用证据；外部访问、区域、出网、隐私/成本、Edge 执行限制需要按账户方案确认。官方 Cron 文档建议每任务不超 10 分钟，并写明运行记录表：[Cron](https://supabase.com/docs/guides/cron) | 如果无已有资源且境外云端访问可接受，作为最简托管数据库候选；与 CloudBase 二选一，不同时维护两套 |
| **Cloudflare Workers + D1** | 静态资产、API、Cron、轻量 SQLite 式 D1 可组合；官方计费与限额清楚：[定价](https://developers.cloudflare.com/workers/platform/pricing/) | 免费 Worker 单次 CPU 预算较紧；需要自己设计数据库迁移、任务锁、运行历史、认证和管理 UI；需验证用户访问和行情源网络 | 适合较轻 API/cron 技术栈；此项目有分析型数据和用户持仓，若没有现成 Cloudflare 资源，不作为第一选择 |
| **Vercel + Cron** | 前端静态部署及 Functions/cron 路径接入直接 | 官方说明 Hobby cron 仅每日一次且精度在小时级；失败不自动重试；付费版支持更细频率但仍需独立持久化和幂等：[计划与精度](https://vercel.com/docs/cron-jobs/usage-and-pricing)、[失败/重试](https://vercel.com/docs/cron-jobs/manage-cron-jobs) | 当前开盘后、收盘后任务不适合 Hobby 计划；若未来确认已托管在 Vercel，只保留为前端/函数候选 |
| **GitHub Actions** | 易做仓库 CI、测试、每日维护任务；不需要前端常开 | `schedule` 可能因负载延迟或丢弃；只在默认分支配置运行；不是用户数据 API/DB：[GitHub schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows) | 保留给 CI 和非关键批处理；不作为投资数据日内定时服务的唯一 scheduler |

**暂定主方案：** “先确认已存在的资源；若没有，CloudBase 或 Supabase 二选一”的决策门，而非现在承诺一个未验证的云项目。考虑用户的中文场景，若其已有腾讯云且该环境可达所需行情源，CloudBase 为暂定主候选；若无腾讯云资源但可稳定访问 Supabase，则 Supabase 为备选/可能主选。不能仅凭地区推测作最终决策。签约、部署、启用付费资源或上传持仓前，先向用户呈现具体账号、区域、数据流和费用。

## 10. 分阶段实施计划

| 阶段 | 内容 | 交付物 | 验收门 | 用户需确认/可能成本 |
|---|---|---|---|---|
| Gate 0：本报告 | 现状与风险、方案比较、路线图 | `docs/UPGRADE_AUDIT.md` | 已区分事实/未知并指出可复用内容 | 用户审阅并批准 Gate 1；不产生服务费用 |
| Gate 1A：项目底座与资源核查 | 建立/连接 Git 正式仓库、基线归档、核查已有云资源、选主方案/备用方案、数据流和威胁模型 | Git 基线、环境清单、ADR、数据迁移计划 | 可还原原型；确认云区域/访问方式/预计费用；无密钥入仓 | 用户确认仓库和云账号/区域；资源可能计费 |
| Gate 1B：本地模块化与兼容层 | 将 HTML 逐段迁入模块化应用；定义数据 schema 与纯计算 API；旧页面/导出先保留 | UI 骨架、domain types、计算模块、基础测试、可运行本地预览 | 原功能在本地不丢；基础录入与备份流程通过测试 | 无必要外部费用 |
| Gate 2：持仓契约与迁移 | taxonomy 拆分、字段版本化、CSV/Excel 粘贴预览、产品核验和本地旧 JSON 迁移 | schema migration、导入向导、字段差异报告、回滚包 | 迁移前后数量/金额/盈亏/名称一致，用户确认后再保存 | 用户需从原浏览器导出备份；绝不自动读取 localStorage |
| Gate 3：计算与组合可视化 | 用纯函数重做收益与风险统计；类型、资产类别、地域、平台、币种 drill-down | 数据口径说明、可视化总览、计算测试 | 多币种隔离、覆盖率正确、未知数据透明、测试覆盖关键边界 | 不需云数据之前可本地完成 |
| Gate 4：数据源与云服务最小切片 | 用户确认平台后，建认证/API/DB/任务运行记录；接一个可靠产品/行情源 | 云 API、schema migrations、Source cards、run history | 一个真实源端到端成功；失败显示过期而非新值 | 用户填写云端密钥/控制台设置；费用需预估 |
| Gate 5：自动化市场监控 | 按交易日与数据源能力更新市场数据、分类和指标，支持手动运行/重试 | Job A-E 逐步落地、状态页、告警策略 | 幂等、超时、失败重试、时区/假期/过期验证 | 数据源条款与付费额度核准；通知渠道需用户指定 |
| Gate 6：后端 AI 研究 | 用户选择模型和字段范围；后端组装研究上下文、结构化输出、校验并存报告 | Privacy settings、AI API proxy、report history、成本限制 | schema/来源/反方/不操作校验；数据不足时拒绝交易方向；模型失败回退 | 明确模型供应商、数据字段、预算；会产生可变 API 费用 |
| Gate 7：安全、恢复与部署验收 | 权限审查、日志脱敏、备份恢复、真实云部署与端到端运行 | 最终报告、部署/恢复/数据源/AI说明 | 升级 Prompt 规定的流程 A-H 通过；未实测项目仍标为未完成 | 用户确认生产部署和潜在费用；无交易接入 |

阶段可以拆分，但不得越过用户确认点。Gate 0 用户批准后才能开始 Gate 1A；配置/启动付费资源、上传真实持仓或调用外部 AI 前另行说明数据范围与成本。

## 11. 关键风险登记

| 风险 | 等级 | 影响 | 缓解方式 |
|---|---|---|---|
| 唯一应用文件未纳入版本控制 | 严重 | 修改失败难以恢复，无法做可靠阶段验收 | 建立 Git 初始基线；保留原始 HTML 和 JSON 独立备份 |
| 用户现有持仓只在浏览器 localStorage | 严重 | 后端无法读取；浏览器数据丢失会影响唯一持仓记录 | 明确引导用户导出；迁移前备份、预览、差异校验与撤销 |
| 当前工作环境未显示任何云资源 | 高 | 可能错误选择供应商、区域和成本方案 | 先由用户确认账户/项目存在性；仅只读审计；主备方案保留决策门 |
| 市场数据覆盖、授权与净值延迟 | 高 | 过时/不一致数据带来误导性收益和风险建议 | 为每源记录许可、延迟、时区、交易日、来源和健康度；失败明确 stale |
| 中国及海外外部源网络可达性差异 | 高 | 定时任务失败或可查数据与用户环境不同 | 在选定部署区域做真实源探测；设置有限备用源和故障状态 |
| 手工盈亏口径不能还原真实收益 | 高 | 反推成本、组合收益率偏离平台真实计算 | 估算标签、数据覆盖、按币种和口径分组；避免交易结论依赖该单指标 |
| 分类穿透滞后/错误 | 高 | 国别、行业及集中度得出错误结论 | 记录分类源/日期/置信度；未知不猜；用户覆盖保留原始值 |
| 持仓/财务数据泄露给第三方模型或日志 | 严重 | 个人财务隐私暴露、未经同意外传 | AI opt-in、最少必要字段、服务端密钥、日志脱敏、明确费用/数据去向 |
| 任务重复/并行写入 | 中高 | 重复数据、错误风险指标、重复通知 | 幂等唯一键、job run 状态、防重锁、可重跑与重试上限 |
| 投资建议过度自信或让用户冲动交易 | 严重 | 财务损失及情绪加剧 | 保留禁交易约束；输出事实/推断、证据反方、不操作与资料不足拒答 |
| 云端备份让本地设备遗失变成云端永久错值 | 中高 | 错误录入同步污染 | 更新差异确认、撤销版本、备份恢复演练 |
| 供应商费用或条款变化 | 中 | 非预期费用、接口中断 | 低频任务、费用上限/预算提醒、可替换 Adapter、定期复审价目与条款 |

## 12. GATE 0 验收与未决问题

### 已完成

- 已核验目录里只有单文件本地 MVP 与两份说明；未发现源码仓库、Git、框架、后端、数据库、测试、任务或部署配置。
- 已把现有功能、持仓字段、存储、计算、产品查询、AI、备份和主要缺口映射到证据。
- 已识别可保留的原型与必须补齐的系统边界。
- 已给出目标架构、前后端/云/图表比较、分阶段计划和风险清单。
- 没有修改 HTML 或其他业务逻辑。

### 仍待确认，不能从当前项目材料推断

1. 是否有未放入当前工作目录的 GitHub/Git 远端或可连接的源仓库。
2. 用户是否已有腾讯云、CloudBase、Supabase、Cloudflare、Vercel 或其他云资源，以及所在区域。
3. 用户是否同意在云端存储持仓；可接受的数据字段、区域、访问与备份策略。
4. 主要使用地、是否需要中国大陆网络稳定性、允许的部署区域。
5. 可接受的月度基础设施与市场数据支出上限。
6. 是否愿意为应用内 AI 把指定持仓字段发送给哪个模型供应商。
7. 当前浏览器中是否有需要迁移的 localStorage 数据；迁移需要用户主动导出 JSON。
8. 目标访问方式：私有本地应用、个人登录云站点，还是仅限家庭共享。

审计已按现有证据完成。由于当前材料没有 Git 仓库或部署环境，云平台与运行模式仍应作为 Gate 1 的用户确认项，而不是现在创建或迁移资源。本报告是可审阅的 Gate 0 交付物；后续 GATE 1 尚未开始。
